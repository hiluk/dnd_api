# Генерация характеристик и производные значения персонажа

Дата: 2026-10-31. Затрагивает `dnd_api` и `dnd_app`.

## Цель

Персонаж создаётся по правилам «Книги игрока» D&D 5e: характеристики генерируются одним из
трёх официальных способов, бонусы расы применяются автоматически, а модификаторы, хиты, класс
доспеха, инициатива, скорость, бонус мастерства и спасброски вычисляются. Источник правды —
сервер: клиент не может создать персонажа в обход правил.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Строгость | Сервер проверяет все способы генерации и сам бросает кубики |
| Переброски 4к6 | Без ограничений; набор подписывается сервером, чтобы его нельзя было подделать |
| Старые персонажи | Удаляются миграцией |
| Где считаются производные значения | Только на сервере; клиент получает их через превью |
| Уровень при создании | Всегда 1 (повышение уровня — отдельная задача) |
| Класс доспеха | Только без доспехов (снаряжение — отдельная задача) |

Вне рамок: повышение уровня, текущие хиты, снаряжение и доспехи, подрасы, предыстории, навыки.

## Сервер

### Модель

`Character` хранит исходные данные, итоговые значения вычисляются при чтении:

- `GenerationMethod`: `StandardArray = 1`, `PointBuy = 2`, `Roll = 3`;
- базовые характеристики (таблица `character_stats`, значения до бонусов расы);
- `BonusChoices`: список характеристик, выбранных для бонусов расы «на выбор».

Новый enum `Ability`: `Strength = 1`, `Dexterity = 2`, `Constitution = 3`, `Intelligence = 4`,
`Wisdom = 5`, `Charisma = 6`.

Справочники получают структурные поля (текстовые поля для интерфейса не меняются):

- `Asi.Ability` (`Ability?`) — характеристика; `null` у бонуса на выбор;
- `Asi.Choices` (`int`, по умолчанию 1) — сколько разных характеристик выбирается для бонуса на выбор
  (у полуэльфа 2);
- `CharacterClass.HitDie` (`int`) — 6, 8, 10 или 12;
- `CharacterClass.SavingThrows` (`Ability[]`) — две характеристики спасбросков.

`CatalogSeed` заполняет новые поля; сидер обновляет их в существующих базах.

Миграция удаляет всех персонажей и добавляет колонки.

### Правила (`CharacterRules`, слой Application, без зависимостей от БД и HTTP)

Способы генерации:

- **Стандартный набор:** база — перестановка `15, 14, 13, 12, 10, 8`.
- **Покупка очков:** каждое значение 8–15, стоимость 8→0, 9→1, 10→2, 11→3, 12→4, 13→5, 14→7,
  15→9, сумма ≤ 27.
- **Броски:** токен валиден и не просрочен, база — перестановка подписанных значений.

Бонусы расы: фиксированные применяются автоматически; для каждого бонуса на выбор указано ровно
`Choices` разных характеристик, не совпадающих с фиксированными бонусами расы. Итог ≤ 20.

Производные значения (1 уровень):

| Значение | Формула |
|---|---|
| Модификатор | ⌊(значение − 10) / 2⌋ |
| Бонус мастерства | +2 |
| Хиты | `HitDie` + мод. Телосложения, минимум 1 |
| Класс доспеха | 10 + мод. Ловкости; Варвар: + мод. Телосложения; Монах: + мод. Мудрости |
| Инициатива | мод. Ловкости |
| Скорость | из справочника расы (ходьба) |
| Спасброски | мод. характеристики + бонус мастерства, если спасбросок класса |

Ошибки — `ValidationProblemDetails` с сообщениями на русском, например «Потрачено 29 очков
из 27», «Значение 14 использовано дважды», «Полуэльф выбирает 2 разные характеристики, кроме
Харизмы», «Результат бросков недействителен или устарел, бросьте заново».

### API

- `POST /abilities/roll` → `{ values: int[6], token: string }`. Каждое значение — 4к6 без
  наименьшего. `token` — подпись значений и времени через ASP.NET Data Protection, живёт 1 час.
  Без хранения в БД. Требует авторизации.
- `POST /characters/preview` — тело `CharacterDraftDto`
  (`characterRace`, `characterClass`, `generationMethod`, `baseStats`, `bonusChoices`, `rollToken?`)
  → `CharacterSheetDto` (итоговые характеристики, модификаторы, производные значения, спасброски)
  или 400.
- `POST /characters/create` — `CharacterDraftDto` + `name` → 201, `CharacterDto`.
- `GET /characters`, `GET /characters/{id}` → `CharacterDto`: `id`, `name`, `level`, раса, класс,
  `generationMethod`, `baseStats`, `bonusChoices` и `sheet` (`CharacterSheetDto`).

## Клиент

Шаги мастера: раса → класс → способ генерации → распределение → выбор бонусов расы (только если
у расы есть бонус на выбор) → итог и имя. «Назад» работает через `previousState`, как сейчас.

Распределение:

- **Стандартный набор:** у каждой характеристики выпадающий список незанятых значений.
- **Покупка очков:** +/- в диапазоне 8–15, счётчик «Осталось очков: N»; «+» недоступен, если
  очков не хватает.
- **Броски:** «Бросить» → шесть значений с сервера, распределение как у стандартного набора,
  кнопка «Перебросить».

Подсчёт очков и занятость значений клиент делает сам (это интерфейс), итоговая проверка — на
сервере.

Начиная с шага распределения мастер запрашивает `/characters/preview` (дребезг 300 мс) и
показывает итог: «Сила 16 (+3)», хиты, класс доспеха, инициативу, скорость, спасброски. Ошибка
правил показывается на текущем шаге.

Экран персонажа показывает итоговые характеристики с модификаторами, блок производных значений и
спасброски. Карточка в списке не меняется.

Код: `StatsCubit` заменяется кубитом распределения с тремя режимами; `CharactersRepository`
получает `preview` и `rollAbilities`; модели персонажа расширяются полями из API.

## Тестирование

- Сервер, юнит-тесты `CharacterRules` по таблице: повтор в стандартном наборе, 7 и 16 при
  покупке, перерасход очков, подделанный и просроченный токен, ошибочный выбор полуэльфа,
  хиты волшебника с Телосложением 8 (5), класс доспеха варвара и монаха, ограничение 20.
- Сервер, интеграционные тесты: `/abilities/roll`, превью, создание каждым способом, отказ при
  подмене бросков.
- Клиент: кубит распределения (очки, занятость значений, переброс), блок мастера (шаг выбора
  только у полуэльфа), разбор ответов репозитория.
- Вручную в браузере: создание персонажа каждым из трёх способов.
